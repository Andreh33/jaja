# Desktop CRT and camera opening — QA

## Scope

Desktop-only television surround for the existing live Studio. The user subsequently requested a more side-on angle, desaturated casing, stronger wear, better materials, live analog screen effects, and a desktop camera pull-back opening with real preloading. Mobile keeps its original browser layout and curtain transition.

## Design and implementation

- Shared CSS 3D space for case, bezel, glass and live HTML. Text remains above the television in the hero stacking order.
- Slate-blue plastic, generated material map, irregular vector abrasion, vents, case seam, recessed controls, glass rim reflections and a subdued halo.
- Scan drift, RGB phosphor and rolling beam; brief tuning interference on pointer-driven channel/navigation changes. No strobing or forced sound.
- Analog movement pauses offscreen, while the document is hidden, in the expanded Studio and with the pulse control. The tube button disables treatment. Reduced-motion users get a static tube surface.
- Physical channels call the preview's navigation routine, including menu closure, keyboard focus and instant scroll reset. Expansion restores focus to the physical trigger.
- Opening preloads current same-origin home image resources, logo, fonts and desktop texture. External client websites are deliberately not preloaded. Network deadline 4200ms; overall fail-safe 7000ms; Skip/Escape always available.
- Desktop opening holds the brand moment then projects its live logo plane into the real four corners of the glass. Dense projective keyframes prevent the twisting path produced by interpolation of only two matrices.
- Mobile curtain motion remains 2500ms after resource readiness. The existing owner-approved reduced-motion exception remains scoped to the first-visit brand opening.

## Review

| Before | After | Why |
| --- | --- | --- |
| Two-matrix camera interpolation twisted midway | 25 geometrically interpolated projective frames | Camera now follows the screen corners instead of the browser's ambiguous matrix decomposition |
| External channel change could leave a Studio menu open | Same navigation routine as the screen's own controls | Preserves menu, scroll and keyboard contracts |
| Moved helper tools could overlap the hero footer | Desktop footer spacing added without changing the composition row | Keeps the headline coordinates and separates the controls |

Motion review: no unresolved feel-breaking issue identified in the scoped code; transform/opacity-only motion, bounded UI feedback, interruptible toggles, explicit pause and reduced-motion behavior. General code review: no remaining reachable defect found in the reviewed scope.

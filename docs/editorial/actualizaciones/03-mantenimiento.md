# Mantenimiento web: qué tareas conviene dejar por escrito

El mantenimiento de una web consiste en atender lo que necesita para seguir cumpliendo su función: revisar cambios técnicos, conservar una forma de recuperación y responder cuando algo deja de funcionar. La etiqueta «mantenimiento incluido» resulta más útil cuando se acompaña de tareas y responsables concretos.

En Latech, la referencia de hosting y mantenimiento es **60 €/mes para una web y 80 €/mes con tienda online, IVA no incluido**. La creación se presupuesta aparte, desde 600 €. El alcance de soporte, cambios e integraciones se confirma en la propuesta; esta guía explica qué conviene preguntar, sin sustituir las condiciones acordadas.

## Separa tres tipos de trabajo

**Mantenimiento técnico.** Atiende el software y sus dependencias, la configuración necesaria para servir la web y los problemas detectados en los recorridos existentes.

**Operación cotidiana.** Incluye tareas como revisar una solicitud, actualizar horarios o mantener el catálogo. Hay que decidir qué hará el equipo del negocio y qué encargará al proveedor.

**Evolución del producto.** Añadir una zona privada, conectar un sistema nuevo o transformar el proceso de compra puede requerir un proyecto específico. No conviene tratar una ampliación grande como si fuera un cambio de texto.

Esta separación evita discusiones cuando llega una petición nueva. Una misma agencia puede encargarse de los tres grupos, pero el presupuesto debe explicar qué cubre cada servicio.

## Una copia sirve cuando se puede restaurar

Pregunta qué se copia: contenido, base de datos, archivos y configuración pueden necesitar mecanismos diferentes. Define dónde se guarda la copia, quién puede recuperarla y qué procedimiento se seguirá para comprobar la restauración.

No basta con dar por hecho que el alojamiento conserva todo. Una prueba de recuperación debería indicar qué se restauró, en qué entorno y qué funciones se comprobaron después. Acuerda la frecuencia y la retención que necesita tu negocio; no todos los sitios tienen el mismo volumen de cambios.

## Cambiar de tecnología no elimina el mantenimiento

WordPress puede ampliarse mediante código y herramientas de su ecosistema. Una aplicación con Next.js también utiliza software y puede tener autenticación, administración, datos e integraciones. La arquitectura cambia qué tareas hay que revisar, no convierte la web en un sistema sin responsabilidades.

Por ejemplo, en la reforma de Latech se revisan editor, formularios, juegos y presupuestos. Algunos son contenido del servidor y otros necesitan interacción del navegador. Esa distribución es parte de la arquitectura de componentes que documenta [Next.js](https://nextjs.org/docs/app/getting-started/server-and-client-components); no acredita por sí misma una seguridad o velocidad determinada.

## Qué probar después de un cambio

Elige los recorridos importantes para el negocio. En una web de servicios puede ser encontrar una oferta, leer sus condiciones y preparar una solicitud. En una tienda, añade variantes, cesta, cálculo del total y pedidos de prueba. Si hay administración, verifica que las acciones privadas siguen exigiendo el acceso correspondiente.

Guarda una lista breve de comprobaciones repetibles y un procedimiento para volver a la versión anterior cuando sea necesario. El objetivo es detectar una regresión antes de que afecte a una tarea importante, y saber qué hacer cuando ocurra.

## Cinco acuerdos que merece la pena cerrar

1. Canal de soporte y forma de priorizar incidencias.
2. Tareas incluidas y cómo se estima una ampliación.
3. Alcance de copias y comprobación de restauración.
4. Responsables del dominio, las cuentas y los contenidos.
5. Procedimiento de entrega de accesos y salida del servicio.
